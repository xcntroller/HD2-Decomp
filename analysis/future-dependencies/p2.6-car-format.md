# Car packed version10 and restore owners

This closes the byte-layout boundary of004F7650/004F8510/004F7300. Whole Car
restoration remains partial: real model/mesh/collision/part receivers and the
instruction-sensitive tipped-pose correction are required. No gameplay implementation
or runtime compatibility test is claimed. The fingerprint and new instruction
anchors are in [manifest](evidence/manifest.json); the complete numeric field
map is [car-packed-v10.json](evidence/car-packed-v10.json). Raw offsets are used
where no consumer establishes a meaningful field name.

## Envelope and size correction

Car004DD350 writes outer10000: DWORD byte count then the packed buffer. The
buffer begins version DWORD10 and another DWORD computed total bytes. Reader
004DD750 allocates the outer count, reads into it, calls004F8510, frees the buffer
and ignores the result.004F8510 checks ONLY version==10 before mutation; its
length argument does not exist. The internal size DWORD is not consulted.
There is no demonstrated support for another packed version.

The prior research size formula was incomplete. Correct size is:

`0x174 +12*P +20*G +4*sum(n0+n1) +20*A +100*W`.

P=(end598-begin594)/32; G is the number of matched native658/668 geometry pairs;
A=CarFB0; W=Car7C0. Each geometry pair contributes its20-byte header and all
changed vertices from LOD0 and, when source mesh+44>1, LOD1. Size helper assembly
004F74EC/004F7500 and004F75D1/004F75E5 increments those counts and adds four bytes
per changed vertex. Final004F7634..004F763E uses the accumulated bytes. Ghidra
lost these live values; the displayed C return omits them. Do not underallocate
or treat deformation data as a separate optional chunk.

The JSON maps every written header byte to its native offset or operation:
108 nonoverlapping fields cover000..170 inclusive.171..173 are unwritten allocation
padding. Do not infer zeros or serialized state there. All scalar copies are four
raw bytes unless listed as BYTE; no native pointer appears in the fixed header.

## Variable sections, no nested chunk headers

All four sections follow the fixed header in order. Records occupy ascending
output indices, even where the writer fills them by reverse iteration.

1. P point records,12 bytes each: DWORD004F4040(32,point), DWORD native594[i]+10,
   DWORD native594[i]+14. Point comes from actual frame world position transformed
   through the Car's current coordinate system. Reader004F4110 decodes and finds
   nearest existing594 frame (reverse search, strict squared-distance comparison);
   writes its+10/+14. No actor factory or saved frame name exists here.
2. G geometry records, each20+4*(n0+n1) bytes: DWORD geometry name hash,
   DWORD668-record+24, DWORD n0, DWORD n1, WORD668-record+38 and two unwritten
   padding bytes. Then n0 packed DWORD vertex changes for LOD0, n1 for LOD1.
   Writer visits668 ascending, matching658 entries reverse by exact model key7B8
   and geometry name strings; size pass visits reverse but counts same matches.
3. A ancillary records,20 bytes each, over nativeFA8 stride40h: DWORD+20,
   DWORD+24, optional pointed object at+28 contributes DWORD+24,DWORD+28,WORD+70.
   Last two bytes unwritten. If pointer+28 is null, those extra10 bytes are also
   unwritten. Reader guards positional index against currentFB0 and pointer before
   applying. Do not turn null object's scratch bytes into initialized state.
4. W wheel records,100 bytes each, nativeF64 pointer vector. JSON lists all25
   DWORDs and order. Includes vec3s70,80,A0,B0,E0; suspension scalar16C;
   fields1B0/1B4/184/188/1D4/1F0; flags1FC saved with bit10h cleared;22C/230.
   Reader skips indices outside existing7C0, copies80→90, computes168=16C*160,
   moves existing frame14C using original local20/24/28 and suspension16C,
   refreshes wheel148 world anchors and50/60 vectors from Car260 and wheel1D8.
   Flags40000400 hide the actual wheel frame. Those derived vectors are not extra
   saved arrays and cannot be restored by copying100 bytes into a wheel object.

## Point and deformation encoding

004F4040/004F4110 use the initialized Car quantization extents100/104/108 and
bias120/124/128. For32 bits allocate10/10/12 bits to X/Y/Z. Encode uses __ftol
of((component+bias)/extent)*mask, packs X thenY thenZ; it does NOT clamp or mask
input components before OR. Y/Z bias additions spill to FLOAT, X remains x87;
preserve conversion/store points. Decode masks each component, divides by mask,
multiplies extent then subtracts bias. Extents/bias are required existing model
metadata and are not in this packed stream.

Geometry hash004F41F0 takes suffix after the last dot of actual frameE8 name,
XORs successive little-endian DWORD groups, zero-padding the final partial word.
Empty suffix→FFFFFFFF. Length1..3 returns zero-padded bytes (not Ghidra's erroneous
return0).004F42F0 reverse-searches existing668 entries; sentinel/missing→-1.
Hash collision chooses the last matching original entry; no uniqueness guarantee.

For each original/deformed mesh vertex, stride20h, include iff squared position
difference>FLOAT0080F53C. Original/current meshes come from actual interface+04,
vertex lock+04(0), unlock+08. Encode each coordinate difference with
__ftol(delta*FLOAT00810548), mask3Fh, and combine:
`(vertexIndex<<18) | ((qx&63)<<12) | ((qy&63)<<6) | (qz&63)`.
Writer scans vertices reverse but fills each array backward, preserving ascending
indices. There is no saturation: six-bit overflow wraps. Reader sign-extends each
six-bit component and reconstructs baseline position+signed*FLOAT0080FB18.
Constants and their exact FLOAT values are recorded in JSON. Preserve x87 tests,
__ftol and stores rather than replacing with a rounded vector quantizer.

Reader resolves hash, finds/reuses or creates the actual658 baseline association,
updates geometry+24/+38 (kind3 invokes00500DA0 instead),004FEFD0 and visibility,
locks meshes and applies both LOD blocks, invalidates through real mesh/frame
receivers(+AC/+2C/+14/+24). These are actual retained mesh owners, not serialized
vertex buffers owning a replacement scene. Missing hash skips its entire saved
record by counts. Malformed indices/counts are not safely bounded by buffer size;
original per-loop guards are not general validation of decoded vertex indices.

## Other Car chunks, relationships and failure

Outer10001 reverse active part records use004C6660/004C68B0.2000 contains seven
DWORDs118,11C,14C,150,154,E0,E4;2001 contains FLOAT from existing158 virtual0C.
Reader puts that FLOAT at158+50 and rebuilds actual part frame transforms via
00464A40/004C6CB0/0041D180. Existing frames13C/140 and158 must exist. This is
not an actor reference stream. No saved native handles may be fabricated.

10006 uses004E0F70/004E1230 with ECX=Car+24E0 (004DD6C8). Reverse records:
10000 DWORD index, BYTE entry10, DWORD entry04, DWORD entry08 from owner28 vector;
10001 DWORD index,DWORD element04 from owner48 stride0C vector;
10002 BYTE owner64,DWORD owner0C. No Human actor ID is decoded by these readers.
The earlier seat/attachment label was unproved; keep this subowner distinct until
its actual producers identify those fields. Original index check accepts index==count
and some invalid/unknown paths do not leave chunks. Do not port that as safe bounds.
Human-mounted identity is the already established Human1001/1006 actorID path.
Car loading must provide seats/occupant callbacks before Human restoration; this
packed stream neither creates passengers nor schedules a deferred identity fixup.

Version rejection occurs before destructive004E95B0; all later errors can leave
mutated pose, geometry, registration or effects. No rollback or packed length
validation exists. Unwritten padding can leak allocation contents; deterministic
zero padding in a native writer would be an explicit safe deviation, not recovered
original bytes. Checked lengths/count arithmetic/indices, allocation cleanup and
failure propagation are also reasonable explicit deviations. Existing owners must
perform teardown; nested buffers freed by the outer reader do not undo world mutation.

Smallest batches: B26.actors.car.layout (fixed/variable byte codec, original padding
policy explicit); B26.actors.car.mesh (actual baseline/deformed mesh ownership,
quantization, invalidation); B26.actors.car.restore (detach→pose correction→derived
rebuild→field/part replay→collision publication). Layout availability does not
promote the parent batch. Desktop acceptance requires real damaged/deformed,
moving, occupied vehicles across load/repeat/failure; no such test was performed.
