## Receiver and file envelope

`006C39F0(application, filename-string-ref, live-byte)` writes.
`006C3340(application, filename-string-ref, live-byte)` reads. Caller supplies
path; do not add a universal profile prefix inside these receivers. Both choose
the retained game at menu+5B8 when active state virtual+1C reports type11;
otherwise use the active state directly. Live branch requires game type1 and
rejects byte `0086922C`. Filename-string temporary/refcounts are caller-owned.
Fresh local ChunkFile owns its handle and chunk stack through close/destruction.

Non-live writer opens write mode, invokes `006B71C0`, closes, then calls
`006B76D0 → 006B3C90` for filename/profile publication. The reader opens, resets
application preparation through `006B6FF0`, invokes `006B72B0`, closes and returns
low-byte1; it does not propagate the nested reader result. Missing open returns0.

Live writer opens/truncates BEFORE checking current mission ordinal. Negative
ordinal closes/fails, so this is not an atomic replacement protocol. Root is
`0x4e8c`, then child `0x0bb6` containing DWORD flattened mission ordinal.
For root1, add `006B9030(0)` to `006B8EC0(root)`. Then write preparation wrapper,
set byte from `006AE510` on actual application+20 owner to1, invoke game writer
`0069C8E0`, reset byte0, leave root, close, publish filename. Writer returns the
game writer low byte, not a verified all-writes result.

Live reader performs three IGraph clear/present pairs first. It requires EXACT
root `0x4e8c`, first child `0x0bb6` and matching current flattened mission.
Only then reset application preparation, read preparation wrapper, set the
application+20 byte1, call game reset `0069C390(false)`, restore `0069CFC0`, clear
byte0 and close. Static anchors `006C368B..006C36D6` prove actual ECX owners and
call order. Neither nested reader result is tested here. The eventual outer
success does not prove successful restoration. No transaction, rollback, temporary
file rename, checksum or cancellation protocol is established by these bodies.

Existing `validate_profile_quick_save` (`006C47C0`) has a WEAKER metadata gate:
root>0x4e8b, tag0x0bb6 and signed mission<count (negative is not rejected).
Reusing it as the full loader would silently change compatibility. Existing
profile finalizer `006B03B0`, promotion `006B0520`, `profile_load.h` and
`profile_save.h` are reusable metadata/profile work, not world persistence.

## Chunk framing

Reuse [ChunkFile](../../recovered/io/chunk_file.h): little-endian u16 tag + u32
total chunk size INCLUDING six-byte header; writer begins with zero size and
backpatches on leave. Read leave seeks to recorded end. DTA write/open/seek/
close semantics and ignored write results are already recovered. Native bounds
failures must be described as guards, not invented original compatibility rules.
Original short-header loops can retain prior tags; malformed inputs require
focused audit before exposing a production reader.

## Restart, resume and failure boundaries

Pause menu actions B5/B6/B7 write command1/2/3 to006DC940 receiver and status15;
B8 sets retained game+1C=2 and falls through to status16. Controller status15
restores game before destroying menu, sets status1/+6E=1 and restores audio;
status16 restores owner then0069A500 (sets status6 and delays). Status11 unwrapping
is another path. The application command consumer below resolves B5 as restart, B6 as quick save
and B7 as quick load. Main resume uses the separate command6 receiver described
below; final path/preparation leaves still remain. No UI operation is declared
ready from captions alone.

No rollback after partially destructive squad/Script/module mutation is proven.
The application+20 flag is cleared on the observed normal return, not a proven
all-exception guarantee. Recover each original failure branch before choosing
native cleanup; test prefix failures and repeated attempts. Cancellation before
commit and ordered release of borrowed actor/frame/context links remain gates.

Static work possible without a running world: byte layouts, version/mission
checks, vtable targets, state receiver routing, serializer call order and profile
publication. Live world round trips, pending scripts/timers, inventory identity,
restart determinism and retained owner coherence require reconstructed runtime
plus user desktop acceptance. No compatible original live-save sample has been
validated in this research checkpoint.

## Resolved application operation dispatcher

`006DCAE0` consumes application+04 AFTER controller variable/fixed/update and
network service calls, before present. Offline mode7, current status1/6/5, real
game getter00698500 and game+6E are required. It saves IGraph flags, clears bit20h,

existing world through its reset path, not an unconditional scene reconstruction.
`0069C390(true)` sets game status5 and +20=500, while its false path has distinct
actor reset/spawn conditions. Module/actor restart tails remain mandatory leaves.

`006C38F0` chooses pending explicit filename for command4, otherwise006B7A00
