Tag2700 (0xA8C) is **Whenever state**, not a generic pending-event queue. Writer
and reader iterate the already compiled context+80/+84 list in ascending order;
each record+0C DWORD period, +10 DWORD elapsed, +08 BYTE enabled. There is no
saved count, expression or jump PC. Reuse `MissionScriptProgram::whens`; compilation
must reproduce count/order/expression/PC before reading nine bytes per record.
Tick004167B0 visits whens in reverse, adds500 to enabled elapsed, triggers only
when elapsed>period, subtracts period once, sets ready/PC, disables that entry
and clears Delay. It polls only while FC>500, subtracts500 each pass, then adds
new elapsed. Restoring just elapsed without enabled/period would change behavior.

## Frame references and lifetime

Tag2400 contains exactly one child2450 per existing+90 slot: raw NUL-terminated
frame name. **2450 is not an error-string chunk**; that previous statement was
incorrect. The diagnostic strings describe failures while resolving these names.
Reader releases every old referenced frame through its actual virtual0 and zeros
the slots before parsing. Nonempty names try actual game scene+7C(maskCFFFF), then
scan installed item/model entries via0098B808/0098B810 and007D3AA0(0), then the
Script-owned saved-frame collection004203C0. Fallback compares actual model names;
it is not a reserved magic-name namespace or an actor-index fixup. A temporary
normalized name copy exists, but the exact normalization helper's semantics must
not be generalized to all resource keys. Empty names leave null. Successful
resolution increments actual frameE4 retain count; missing name leaves null and
collects a Frame-not-found diagnostic. The owning scene and these resolver
collections must outlive retained slots; clear releases them before world death.

Tag2600: pending PC DWORD plus u16 string byte count and NUL-terminated frame name
via00414DD0. It only exists when pendingPC!=-1. Reader writes pendingPC, resolves
scene+7C directly into context+28; absent frame sets pendingPC=-1. Unlike reference
slots, no item/model fallback or retained-slot increment occurs in this branch.
The tick compares pendingPC with current PC: if different it clears frame and
pending index; if equal it waits for actual animation channel advancement before
00416CF0. Existing source currently rejects pending_pc_!=-1: persistence cannot
make this unsupported async receiver ready. Save/load must preserve actual clip/
channel ownership and module rotation/animation restoration, not skip the wait.

Context kind1/2 tags2800/2900 target derived+108 byte, guarded by virtual+04 kind.
Recover the derived receiver contract before applying those to the base class.
The module restore first retires old contexts and queued rotations, resolves each
binding frame, compiles its saved script through00427730 and then calls00414E30
on that actual derived context. Program layout, frame-slot count, variable
classification and whens count are therefore hard data dependencies. Context
reader can return0 for unknown chunks after releasing old references and changing
fields; no rollback to the prior PC/program is supplied. Some chunk-error paths
return1 after diagnostics; caller result handling must remain explicit.
